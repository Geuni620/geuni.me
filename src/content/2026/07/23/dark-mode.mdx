# appTheme, editorTheme

Excalidraw는 다크모드 구현을 위해 상태를 2개로 관리한다.

```tsx
const [appTheme, setAppTheme] = useState<AppTheme>("light");

// Light 버튼  → appTheme = "light"
// Dark 버튼   → appTheme = "dark"
// System 버튼 → appTheme = "system"
```

`appTheme`는 사용자가 UI에 선택한 값을 관리한다.

```tsx
const [editorTheme, setEditorTheme] = useState<Theme>("light");

// appTheme = light  → editorTheme = light
// appTheme = dark   → editorTheme = dark
// appTheme = system → OS 설정에 따라 light 또는 dark
```

`editorTheme`는 실제 화면에 적용할 값이다.

<br />

# 동작 방식

```tsx
const [appTheme, setAppTheme] = useState<AppTheme>("light");
const [editorTheme, setEditorTheme] = useState<Theme>("light");

useEffect(() => {
  if (appTheme !== "system") {
    setEditorTheme(appTheme);
    return;
  }

  const mediaQuery = window.matchMedia("(prefers-color-scheme: dark)");
  const updateEditorTheme = (matches: boolean) => {
    setEditorTheme(matches ? "dark" : "light");
  };

  const handleChange = (event: MediaQueryListEvent) => {
    updateEditorTheme(event.matches);
  };

  updateEditorTheme(mediaQuery.matches);
  mediaQuery.addEventListener("change", handleChange);

  return () => {
    mediaQuery.removeEventListener("change", handleChange);
  };
}, [appTheme]);
```

## Light/Dark 선택 시

만약 유저가 dark를 선택했다면 다음과 같이 동작한다.

```
사용자가 Dark 클릭
→ setAppTheme("dark")
→ appTheme 변경
→ 리렌더링
→ useEffect 실행[dependency appTheme]
→ setEditorTheme("dark")
→ editorTheme 변경
→ 다시 리렌더링
```

그리고 editorTheme가 실제 화면에 반영되는 것이다.

## System 상태에서 OS 테마 변경 시

이미 `appTheme`이 `"system"`인 상태에서 OS 테마가 변경되면 다음과 같이 동작한다.

```text
OS 테마 변경
→ useEffect 재실행 안 함
→ mediaQuery 변경(onChange)
→ 브라우저가 handleChange 호출
→ updateEditorTheme 호출
→ setEditorTheme 호출
→ editorTheme 변경
→ 리렌더링
```

useEffect는 재실행 되지 않지만 useEffect 내 존재하는 mediaQuery가 변경되고,
`mediaQuery.addEventListener("change", handleChange)`에 의해 editorTheme의 상태가 변경된다.

appTheme은 여전히 `system` 상태를 유지한다.

# useSyncExternalStore로 변경해보기

```tsx
function subscribeToSystemTheme(callback: () => void) {
  const mediaQuery = window.matchMedia("(prefers-color-scheme: dark)");

  mediaQuery.addEventListener("change", callback);

  return () => {
    mediaQuery.removeEventListener("change", callback);
  };
}

function getSystemTheme(): Theme {
  return window.matchMedia("(prefers-color-scheme: dark)").matches
    ? "dark"
    : "light";
}

export default function App() {
  const [appTheme, setAppTheme] = useState<AppTheme>("light");

  const systemTheme = useSyncExternalStore(
    subscribeToSystemTheme,
    getSystemTheme,
  );

  const editorTheme = appTheme === "system" ? systemTheme : appTheme;

  return (
    //...
  );
}
```

## System 상태에서 OS 테마 변경 시

```
OS 테마 변경
→ 브라우저가 `change` 이벤트 발생
→ `callback function` 호출
→ React가 `getSystemTheme` 다시 호출
→ `systemTheme` 변경 (dark or light)
→ `editorTheme` 다시 계산
→ 리렌더링
```

# 상태 + CSS로 변경해보기

처음 dark-mode 구현을 보고 굳이 상태를 2개 관리할 필요가 있을까 싶었다.  
1개의 상태에 변수 1개로 처리할 수 있을 것 같았다.

하지만 appTheme이 System일 경우, OS 요소를 읽는 것까진 가능하지만 화면자체를 리렌더링 시킬 순 없었다.  
고민해보던 중 CSS를 사용하면 어느정도 해결이 가능하다.

```tsx
function App() {
  const [appTheme, setAppTheme] = useState<AppTheme>("light");

  const usesSystemTheme = appTheme === "system";

  return (
    <main
      className="theme-demo"
      data-theme={usesSystemTheme ? undefined : appTheme}
    >
      //...
    </main>
  );
}
```

```css
.theme-demo {
  /* 기본값: light */
}

.theme-demo[data-theme="dark"] {
  /* 사용자가 명시적으로 dark를 선택한 경우 */
}

@media (prefers-color-scheme: dark) {
  .theme-demo:not([data-theme]) {
    /* data-theme이 없을 때만 시스템 설정을 따른다 */
  }
}
```

# 그 간의 고민을 읽어보기

### 1. 최초의 dark-mode

excalidraw의 dark-mode에 대한 issue를 거슬러 올라가면 2020년에 초기안이 개발된 것으로 보인다. [#1148](https://github.com/excalidraw/excalidraw/issues/1148)  
[#2006](https://github.com/excalidraw/excalidraw/pull/2006) PR을 살펴보면, 초기 Dark Mode를 어떻게 구현했는지 확인할 수 있다.

초기는 단촐하다. CSS에 변수를 지정하고 light와 dark 속성에 따라 단순 스타일을 전환시켜서 구현했다. system도 고려되지 않았다.

### 2. 시스템 테마 논의

```css
@media (prefers-color-scheme: dark) {
  /* 자동으로 dark mode */
}
```

[#2025](https://github.com/excalidraw/excalidraw/issues/2025)

하지만 excalidraw 팀은 시스템 OS에 따른 테마 설정을 바로 반영하지 않는다.
그 이유는 macOS를 dark로 사용하는 사람도 UI는 dark이지만 Excalidraw 같은 도화지는 흰 색상이길 원할 수 있다는 점 때문이다.

### 3. 내보내기 테마

[#2026](https://github.com/excalidraw/excalidraw/issues/2026)

이번엔 내보내기 기능에 다크모드를 지원해야할지 말아야할지 고민에 대한 이슈이다.

### 4. 테마 저장과 초기 깜빡임

localStorage로 dark-mode를 저장해뒀다가 사용하는데,
html로 로드될 때 default light mode에서 js가 로드되면서 localStorage를 읽고 다크모드라면 초기 slash 에서 흰화면이 잠깐 보였다가 다크모드로 전환된다.  
이 때문에 html를 불러올 때부터 scripts를 넣어서 해결했다. [#5701](https://github.com/excalidraw/excalidraw/pull/5701/changes)

물론 localStorage와 상태 동기화로직도 포함되어있는 PR이 존재한다. [#5660](https://github.com/excalidraw/excalidraw/pull/5660/changes#diff-7d537bef2a9bbed4a1fbc825d63163ce532bb20b8ea8dfc0ae1d1b296dcf2aecR517-R528)

### 5. System 모드와 두 상태

드디어 우리가 살펴봤던 appTheme과 editorTheme가 나온다.  
useLayoutEfffect와 useEffect를 각각 사용했다.

여기서 useLayoutEffect까지 사용한 이유는 동기화 때문이다.
유저가 dark로 선택했고, 이를 저장했지만, appTheme의 default는 light이다.

만약 해당 유저가 이 페이지에서 새로고침을 한다면 잠깐의 찰나에 light → dark로 appTheme과 editorTheme의 동기화가 발생하는데,
이는 사용자에게 안 좋은 UX를 심어줄 수 있는 것이다.
